# ADR-0031 — Exception messages are resources, one resx per assembly

**Status:** Accepted · **Date:** 2026-08 · **Satisfies:** [NFR-UX-002](../requirements/non-functional.md)

---

## Context

Every message FallbackPlan raised was a string literal at the `throw` site. That reads well — the sentence sits next to the code that decided to say it — and it makes the product English-only in a way no configuration can undo.

[NFR-UX-002](../requirements/non-functional.md) already required externalised strings. Nothing enforced it, and 328 messages accumulated inline before anyone counted.

The messages are not incidental. This is a backup tool, so a person reads one at the worst possible moment — a restore that refused, a blob that failed authentication, a repository the reader will not open. "The recovery footer failed authentication — the blob is damaged or does not belong to this repository (specification 05 §3)" is the product's voice at the moment the product matters most, and it should be available in the reader's language.

## Decision

**Every message a person may read lives in a resx, one per assembly, reached through a generated accessor.**

- Each assembly with messages carries `Resources/Strings.resx`. A translation sits beside it as `Strings.<culture>.resx` and ships as a satellite assembly; no code changes to add one.
- Keys are `<Type>_<Subject>` — the type that raises it, then what it says. `BlobReader_RecoveryFooterFailedAuthentication` says where to look and what happened without opening the resx.
- Placeholders are **positional** (`{0}`, `{1}`), never interpolated. A translator may need to reorder them, and a composite format string is the only form that allows it. Format specifiers survive: `0x{0:x4}` still renders as it did.
- The accessor is generated by [`eng/generate-resources.py`](../../eng/generate-resources.py) and committed. A message with no holes is a property; one with holes is a `Format…` method taking exactly its arguments, with the raw composite string kept private so nobody formats it with the wrong count.

**Per assembly, not one shared resource project.** Two reasons, one of them recent. Layering: `Domain` owning `Domain`'s messages matches how everything else here is arranged, and a shared table couples a CLI string change to the format layer. Closure: [ADR-0021 amendment 1](0021-consume-bodu-via-committed-package-feed.md) had just widened `Repository.Format`'s dependency closure by one package, and that closure is the standalone recovery tool's — adding a project reference to every assembly, including that one, is the same cost again for no gain.

**A generator script, not a source generator.** The .NET SDK has no public resx source generation; the options were a source-generator package in sixteen projects or fifty lines of Python. The repository already generates and `--check`s an artefact this way ([conformance vectors](../../specifications/repository-format/conformance/generate.py)), and a CI step now fails when a committed accessor drifts from its resx — which is what stops "generated" from meaning "stale".

## Consequences

**Positive**

- The product can be translated by adding files. No code change, no rebuild of anything but resources.
- Messages are now enumerable. 328 of them in one place per assembly is the first time the product's voice can be reviewed as a whole rather than encountered one `throw` at a time.
- Duplicate messages collapsed: the same sentence raised from two places is one entry, and therefore one thing to translate.

**Negative**

- The sentence no longer sits beside the code that raises it. Mitigated by keys that name their type and by the accessor's XML docs carrying the message text, so hovering the member shows what it says.
- A missing key returns the key rather than throwing, because throwing while building an exception message replaces a diagnosable failure with an undiagnosable one. That degradation is invisible at runtime, which is precisely why the CI check exists.

**Residual**

Messages *not* covered: `DamageFinding` details, log and telemetry text, and CLI help. Findings and logs are diagnostic records read by an operator alongside the specification, and several are asserted on verbatim by tests; help text is `System.CommandLine`'s to render. Whether those follow is a separate decision, not an oversight of this one.

## Alternatives considered

**One shared `FallbackPlan.Resources` assembly.** One file to translate rather than sixteen, and one accessor. Rejected on closure and layering, above — and the "one file" advantage is smaller than it looks, since translation tooling handles a directory as easily as a file.

**`Microsoft.CodeAnalysis.ResxSourceGenerator`.** The dotnet/runtime approach, and genuinely good. Rejected: it is a package reference in sixteen projects to replace a script this repository already has the pattern for, and ADR-0019 asks every dependency to argue for itself.

**Leave messages inline and translate later.** Rejected as the status quo that produced this: NFR-UX-002 existed the whole time and 328 messages were written anyway. A requirement nothing enforces is a preference.
